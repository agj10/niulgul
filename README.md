# niulgul

사진 조각을 재배치해 다른 얼굴을 만드는 브라우저 작업실입니다. [Spu7Nix/obamify](https://github.com/Spu7Nix/obamify)의 **원본 Rust 변환 함수와 유체 시뮬레이션을 직접 컴파일해 사용**합니다.

## 실행

Node.js 22 이상에서 실행합니다.

```sh
npm ci
npm run dev
```

배포용 파일은 `npm run build`로 생성한 `dist/`입니다. 별도 서버 API나 API 키는 필요하지 않습니다. 카메라는 localhost 또는 HTTPS에서 작동합니다.

이미 빌드했다면 `Start-Niulgul.cmd` 또는 `npm start`로 로컬 미리보기를 시작합니다. 주소는 `http://127.0.0.1:3002/`입니다. 서버는 백그라운드에서 유지되며 PC를 재시작하면 다시 실행해야 합니다.

배포는 [GitHub 저장소의 main 브랜치](https://github.com/agj10/niulgul)를 Railway에 연결하는 방식으로 진행할 예정입니다. 작업을 마치고 검증한 변경은 이 저장소에 커밋하고 푸시합니다. 실제 Railway 연결과 배포는 추후 진행합니다.

## 사용과 해상도

1. 샘플 또는 직접 올린 재료 사진을 선택합니다. 파일 선택과 드래그 앤 드롭을 지원합니다.
2. 목표 얼굴 사진을 선택하거나 카메라를 켜고 **현재 화면 촬영하기**를 누릅니다. 누른 순간의 화면을 정지 사진으로 넣으며, **다시 촬영하기**를 누르기 전까지 같은 사진을 사용합니다. 재료는 항상 정지 사진입니다.
3. 전체 또는 감지한 얼굴 영역에 적용합니다. 얼굴 영역 모드는 배경을 유지합니다.
4. 변환하기를 누르면 원본 방식으로 배치를 끝까지 계산한 뒤 원본 유체 시뮬레이션을 재생합니다.
5. 슬라이더 변경은 촬영한 사진을 그대로 사용해 계산 후 즉시 교체하며, 이동 애니메이션은 최초 변환과 재료·목표 사진 변경 시 재생합니다. 웹캠 화면만으로 결과를 자동 갱신하지 않습니다.

원본 엔진은 정사각형 격자를 사용합니다. 전체 모드는 원본처럼 사진 중앙의 정사각형 구도를 사용하고, 얼굴 영역 모드는 얼굴마다 정사각형 영역을 사용합니다.

**해상도와 디테일은 재료 사진이 기준입니다.** 업로드한 재료를 1,200px로 축소하거나 계산 격자를 128로 제한하지 않습니다. 조각 크기 1px에서는 재료 구도의 각 픽셀을 계산하고, 2px에서는 가로·세로를 절반의 조각 수로 계산합니다. 얼굴 사진의 해상도는 결과 크기를 결정하지 않습니다. 큰 사진을 작은 조각으로 계산하면 원본 알고리즘의 연산량도 크게 늘어납니다.

PNG와 GIF는 재료 구도의 픽셀 크기로 출력합니다. 미리보기만 화면 크기에 맞게 표시합니다. GIF는 화면 녹화가 아니라 저장 시점의 완료된 배치를 고정해 별도로 재생성합니다. 원본 1초 정지와 끝 장면 1초 정지를 포함합니다.

## 원본 코드 사용 범위

- `vendor/obamify/src/app/calculate/mod.rs`: 원본 `heuristic`, `Pixel`, `process_genetic`의 본문을 `core/build.rs`가 그대로 포함합니다. 비용 함수, FRand 시드 12345, 교환 순서, 세대당 시도 수, 반경 감소, 수렴 조건을 변경하지 않습니다.
- `vendor/obamify/src/app/morph_sim.rs`: 파일 전체를 그대로 포함합니다. 힘, 벽 반응, 이웃 탐색, 속도 정렬, 감쇠와 f32 계산은 원본 Rust에서 실행됩니다.
- `core/src/lib.rs`: 브라우저용 메모리 입출력, 원본 중앙 크롭/Lanczos3 샘플링, 기본 목표·가중치 로딩을 연결하는 어댑터입니다.
- `src/simulation.ts`: 원본 Rust 시뮬레이션의 메모리와 시계만 연결합니다. 별도의 TS 물리 모델이나 강제 수렴 보간은 없습니다.
- `src/render.ts`: 원본 seed/JFA/shade 방식을 WebGL2로 표시합니다. 원본의 이웃 검사 순서와 32bit 셀 ID를 사용합니다.
- `src/engine.worker.ts`: 전체 계산이 끝날 때까지 실행합니다. 촬영한 사진도 같은 원본 함수로 계산하며 시간 제한이나 이전 배치에서 시작하는 별도 최적화를 넣지 않습니다.
- `src/export.worker.ts`: 원본 GIF의 8fps, 프레임당 7번 시뮬레이션, 1.5배 재생, 100~140프레임 방식을 사용합니다. 마지막에 조각을 강제로 정렬하지 않습니다.

기본 변환 강도는 원본 `proximity_importance = 13`에 대응합니다. 기본 표현 방식은 원본 RGB입니다. 색감·명암 슬라이더는 원본 함수에 넣는 비교용 이미지의 전처리만 바꾸며, 결과에는 재료의 원래 색을 사용합니다. 기본 샘플 얼굴은 원본 목표와 가중치 이미지를 쓰고, 사용자 얼굴은 원본 사용자 목표와 같은 균일 가중치를 씁니다.

## 빌드와 검증

```sh
npm run build
npm test
```

원본 Rust로 컴파일한 `public/engine/original.wasm`을 포함하므로 일반 실행에는 Rust 설치가 필요하지 않습니다. 소스 해시와 바이너리 해시는 빌드 시 검증합니다.

원본 코어를 수정하거나 재컴파일할 때는 Rust와 wasm32 타깃이 필요합니다.

```sh
rustup target add wasm32-unknown-unknown
npm run build:core
```

`core/Cargo.lock`으로 원본 난수 라이브러리 `frand 0.10.1`과 이미지 처리 버전을 고정합니다.

테스트는 실제 Rust/WASM을 실행해 픽셀 보존, 결정성, 원래 색 유지, 원본 기본 위치 가중치, 강제 보간 없는 시뮬레이션, 최신 설정 처리 순서를 확인합니다. `tests/`의 HTML은 개발 서버에서 실행하는 브라우저 검증용 페이지이며 배포 빌드에는 포함되지 않습니다.

## 개인정보와 출처

사진과 카메라 프레임은 브라우저 안에서 처리하며 서버에 업로드하지 않습니다. 얼굴 감지 모델과 실행 파일도 로컬 제공됩니다. 글꼴만 Google Fonts에서 불러오며 실패하면 시스템 글꼴을 사용합니다.
