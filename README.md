# niulgul

재료 사진의 픽셀을 재배치해 원하는 얼굴을 만드는 웹 도구예요. 색을 가진 조각들이 흘러가듯 움직이며 얼굴의 형태를 만들어요.

[사이트 열기](https://niulgul.up.railway.app/) · [원본 프로젝트 Spu7Nix/obamify](https://github.com/Spu7Nix/obamify)

## 사용 방법

1. **재료 사진**에서 변환할 사진을 고르세요. 이 사진이 결과의 색과 크기를 결정해요.
2. **얼굴 사진**에서 닮게 만들 얼굴을 고르세요. 웹캠으로 촬영한 사진도 사용할 수 있어요.
3. 업로드하거나 촬영하면 편집창이 열려요. 구도와 해상도를 조절한 뒤 **적용하기**를 누르세요.
4. 적용 영역과 변환 설정을 고르고 **변환하기** 또는 **다시 변환하기**를 누르세요.
5. 완성된 결과를 **PNG**, 움직이는 과정을 **GIF**로 저장하세요. **원본 보기**로 재료 사진과 비교할 수 있어요.

처음 접속하면 고양이와 오바마 예시가 자동으로 재생돼요. 이후 사진이나 적용 영역을 바꾸면 마지막으로 적용한 설정으로 다시 변환해요. 슬라이더 값은 버튼을 누를 때만 적용돼요.

### 세 가지 변환 설정

| 설정 | 범위 · 기본값 | 바뀌는 내용 |
| --- | --- | --- |
| 변환 강도 | 0~100% · 약 33% | 높일수록 원래 위치를 지키려는 제약을 줄여 얼굴에 맞게 더 멀리 재배치해요. 0%에서는 원래 배치를 유지해요. |
| 조각 크기 | 1~32px · 1px | 클수록 적은 수의 큰 조각으로 변환해요. 작을수록 세밀하지만 계산량이 늘어요. |
| 표현 방식 | 명암~색감 · 색감 | 명암 쪽은 밝기 차이를, 색감 쪽은 RGB 색 차이를 기준으로 배치해요. 중간값은 두 기준을 섞어요. |

변환 강도는 이전 범위의 0~75%를 현재 슬라이더의 0~100%로 맞췄어요. 기본값은 이전 25%와 같은 강도이며 현재 화면에는 반올림해 33%로 표시해요.

슬라이더를 움직이는 동안에는 현재 결과와 진행 중인 변환을 유지해요. 버튼을 누르면 그 순간의 세 값을 함께 적용하고, 새 결과의 애니메이션을 재생해요. 애니메이션 중에도 **다시 변환하기**를 누르면 재생을 즉시 멈추고 새 설정으로 계산해요. 배치를 계산하는 동안에는 버튼을 비활성화해요. 표현 방식을 바꿔도 출력에 쓰는 재료의 색을 흑백으로 바꾸지는 않아요.

### 이미지 편집과 출력 크기

편집창의 점선은 실제로 내보낼 영역이에요. 재료 편집창은 편집을 시작한 재료 사진의 비율을, 얼굴 편집창은 현재 재료 사진의 비율을 사용해요. 사진을 이동·회전·늘리거나 잘라도 점선 프레임은 고정돼요.

사진 모서리는 가로·세로 크기를, 변은 한 방향의 크기를 조절해요. 자르기 바는 사진의 외곽선을 따라 움직이며 원본 바깥으로 늘어나지 않아요. Shift로 모서리 크기를 조절하면 **그 조절을 시작할 때의 잘린 사진 비율**을 유지해요. 좌우·상하 반전도 지원해요.

해상도 슬라이더는 편집 결과의 긴 변 길이를 정해요. 처음에는 원본의 긴 변과 256px 중 작은 값으로 열리고, 원본 크기까지 올릴 수 있어요. 최종 출력은 **적용한 재료 사진의 가로·세로 크기**를 따라가요. 예를 들어 재료를 256×128px로 적용하면 PNG와 GIF도 256×128px예요. 얼굴 사진을 크게 넣어도 결과 해상도가 커지지는 않아요.

재료 사진의 해상도와 조각 크기는 달라요. 해상도는 출력 이미지의 크기를, 조각 크기는 그 안에서 움직일 조각의 수를 정해요. 조각 크기가 `c`일 때 가로·세로 조각 수는 각각 `round(가로/c)`, `round(세로/c)`이며 최소 1개예요.

투명한 이미지는 불러올 때 흰색 바탕에 합쳐요. 편집 중 사진이 출력 프레임을 덮지 않는 부분도 적용 결과에서는 흰색이 돼요.

### 카메라

카메라는 촬영 버튼을 누른 순간의 화면 한 장만 사용해요. 촬영 후 편집창에서 **적용하기**를 눌러야 얼굴 사진으로 들어가며, 취소하면 기존 사진을 유지해요. 전면 카메라 촬영은 미리보기처럼 좌우가 반전돼요. 기기가 지원하면 전면·후면을 전환할 수 있어요.

## 변환 원리

### 1. 두 사진을 같은 조각 격자로 준비해요

재료 사진은 색을 공급하고, 얼굴 사진은 각 위치에 어떤 색이 있으면 좋을지 알려주는 목표가 돼요. 사진 전체를 변환할 때 재료의 가로·세로 비율을 유지하고, 목표 사진을 그 비율에 맞게 가운데에서 잘라 같은 격자 크기로 맞춰요. 크기 조정에는 Lanczos3 필터를 사용해요.

조각 크기가 1px이면 적용한 재료 사진의 각 픽셀이 조각 하나예요. 더 큰 값을 쓰면 재료를 작은 격자로 먼저 축소하고 그 격자의 픽셀을 재배치해요. 따라서 큰 조각을 사용한 결과는 원본 파일의 모든 픽셀을 그대로 옮긴 결과와는 달라요.

### 2. 색 차이와 이동 거리를 함께 계산해요

어떤 재료 조각을 어느 목표 위치에 둘지 다음 비용으로 평가해요.

```text
색 차이 = (재료 R - 목표 R)² + (재료 G - 목표 G)² + (재료 B - 목표 B)²
거리 제곱 = (원래 x - 목표 x)² + (원래 y - 목표 y)²
비용 = 색 차이 × 목표 가중치 + (거리 제곱 × 위치 가중치)²
```

색 차이가 작으면 목표 얼굴과 색이 잘 맞고, 이동 거리가 짧으면 재료 사진의 원래 구조를 더 많이 남겨요. 위치 비용은 거리의 네제곱에 비례하므로 멀리 보내는 조각에 강한 제약을 걸어요.

**변환 강도**는 위치 가중치를 조절해요. 기본값에서는 31을 사용하고, 강도를 높이면 이 값을 줄여요. 현재 범위의 약 66.7%에서는 원본 엔진의 값인 13을, 최댓값 100%에서는 5를 사용해요. 최댓값에서도 위치 비용을 남겨 이동 거리를 제한해요. 0%는 최적화 없이 원래 순서를 그대로 반환해요.

**표현 방식**은 비용을 계산할 입력 색을 조절해요. 명암 끝에서는 `0.2126R + 0.7152G + 0.0722B`로 밝기를 구하고, 색감 끝에서는 원래 RGB를 사용해요. 이 처리는 배치를 고르는 기준에만 쓰이며, 결과에 칠할 색은 재료에서 따로 보관해요.

기본 오바마 샘플은 원본 프로젝트의 목표 이미지와 위치별 가중치 지도를 사용해요. 사용자가 넣은 얼굴 사진은 모든 목표 위치에 같은 가중치 255를 적용해요.

### 3. 두 조각의 자리를 바꾸며 배치를 개선해요

현재 사용하는 알고리즘은 원본 Rust 엔진의 `process_genetic`이에요. 두 위치를 무작위로 고른 뒤 서로 바꿨을 때 두 위치의 비용 합이 줄어들면 교환해요. 넓은 범위에서 시작해 탐색 거리를 점차 줄이고, 좁은 범위에서 더 이상 개선이 거의 없으면 끝내요.

매 세대에 조각 수의 128배만큼 교환을 시도해요. 난수 시드는 `12345`로 고정돼 있어 같은 엔진과 같은 입력·설정에서는 같은 배치를 얻어요. 전역 최적해를 보장하는 방식은 아니에요.

계산 결과는 **각 목표 위치에 들어갈 재료 조각의 번호**예요. 조각을 새로 만들거나 없애지 않고, 준비된 조각을 각각 한 번씩 사용하는 순열을 만들어요. 그래서 재료에 없는 색을 새로 생성해 얼굴을 채울 수는 없어요. 재료와 목표의 색·밝기 구성이 크게 다르면 닮는 데 한계가 있어요.

조각 크기가 1px이고 사진 전체를 변환한다면, PNG 결과는 적용한 재료 사진의 RGB 픽셀을 각각 한 번씩 사용해요. 이 기준은 업로드 전 원본 파일이 아니라 **편집과 해상도 조절을 마친 재료 사진**이에요.

### 4. 정해진 배치로 움직이는 과정을 시뮬레이션해요

배치 계산과 애니메이션은 별개예요. 먼저 각 조각의 목적지를 정하고, 그다음 원본의 `morph_sim.rs`로 움직임을 계산해요. 조각에는 목적지로 당기는 힘, 가까운 조각과의 반발·끌림, 주변 속도에 맞추는 힘, 화면 경계의 힘과 감쇠가 적용돼요.

화면은 움직이는 조각의 중심점을 기준으로 가까운 영역을 나누는 **보로노이 방식**으로 그려요. WebGL2에서 중심점 배치 → Jump Flooding으로 가까운 조각 탐색 → 해당 재료 색으로 채우기를 수행하므로, 이동 중에는 조각이 다각형처럼 늘어나고 줄어드는 모습이 나타나요.

일반 재생은 경과 시간에 맞춰 초당 60단계로 시뮬레이션하고, 충분히 정착하거나 최대 1,440단계에 도달하면 끝나요. 끝에서 조각을 강제로 격자에 붙이지 않고 실제 마지막 프레임을 남겨요. 기기에서 움직임 줄이기를 설정했다면 애니메이션을 건너뛰고 완성된 배치를 표시해요. WebGL2를 사용할 수 없으면 Canvas 2D로 조각을 그려요.

### 얼굴 부분만 적용하는 방식

얼굴 감지는 브라우저에서 실행하는 **MediaPipe BlazeFace short-range 모델**을 사용해요. 감지 신뢰도 기준은 0.45예요. 얼굴의 위치와 크기를 구한 뒤 이마와 턱 주변까지 여유를 두고, 이미지 안에 들어오는 정사각형 영역으로 만들어 변환해요. 여러 얼굴이 잡히면 감지한 얼굴 영역들을 각각 계산하고, 그 밖의 배경은 재료 사진으로 유지해요.

피부 윤곽만 정확히 따는 마스크 방식은 아니므로 주변 머리카락이나 배경도 포함될 수 있어요. 얼굴이 작거나 옆을 향하면 놓칠 수 있고, 감지 영역이 겹치면 뒤에 그린 영역이 겹친 부분을 덮어요. 얼굴을 찾지 못하거나 감지기를 불러오지 못하면 **사진 전체**로 변환할 수 있어요.

이 모델은 변환할 위치를 찾는 데 쓰여요. 누구의 얼굴인지 판별하거나 두 사람의 신원을 비교하지 않아요. 목표 사진을 자동으로 준비할 때는 가장 큰 얼굴 영역을 사용하지만, 편집창에서 적용한 목표 사진은 사용자가 정한 구도를 그대로 사용해요.

### 첫 화면이 계산을 기다리지 않는 이유

고양이와 오바마의 기본 배치는 원본 엔진으로 미리 계산해 `public/presets/welcome.bin`에 저장해요. 첫 기본 조합에 한 번만 이 배치를 사용해 최적화 계산을 건너뛰고, 움직임은 브라우저에서 실제로 시뮬레이션해요. 이미지와 엔진을 불러오는 시간은 필요해요.

다시 변환하거나 사진·설정이 달라지면 실제 엔진으로 계산해요. 미리 계산한 파일을 읽지 못하면 일반 계산으로 진행해요. 빌드할 때는 입력 이미지, 엔진, 설정 파일과 저장된 배치의 SHA-256을 검사해 오래된 결과가 섞이지 않도록 해요.

## PNG와 GIF 저장

| 형식 | 저장하는 내용 | 색과 크기 |
| --- | --- | --- |
| PNG | 계산된 최종 배치를 격자에 정확히 그린 정지 이미지 | 재료 사진 크기, RGB 유지 |
| GIF | 같은 배치로 시뮬레이션을 다시 실행한 움직임 | 재료 사진 크기, 최대 256색으로 양자화 |

GIF는 화면 녹화가 아니라 별도 Worker에서 생성해요. 시작과 끝을 각각 1초씩 유지하고, 움직임은 100~140프레임을 생성해 반복 재생하도록 저장해요. 프레임 사이에는 시뮬레이션을 7단계씩 진행하고 80ms의 표시 시간을 사용해요.

화면과 GIF는 실제 시뮬레이션의 마지막 모습을 유지하고 PNG는 목적지에 정확히 배치한 결과를 저장하므로, 마지막 모습이 조금 다를 수 있어요. GIF는 팔레트 제한 때문에 색도 달라질 수 있어요.

## 사진 처리와 보관

사진 읽기, 얼굴 감지, 배치 계산, 애니메이션과 파일 생성은 브라우저 안에서 진행해요. 선택하거나 촬영한 사진을 서버에 업로드하지 않아요. 앱 파일, 예시 사진, 얼굴 감지 모델과 WebAssembly 엔진은 사이트에서 내려받아요.

적용한 사진은 같은 브라우저에서 다시 고를 수 있도록 IndexedDB에 PNG로 보관해요. 재료와 얼굴 사진을 각각 최대 12개, 둘을 합쳐 이미지 데이터 최대 64MiB까지 최근 순서로 유지해요. 같은 종류의 동일한 PNG 데이터는 중복 저장하지 않으며, 각 기록의 삭제 버튼으로 지울 수 있어요. 다른 기기나 브라우저와 동기화하지 않고, 브라우저 데이터를 지우면 기록도 없어져요.

## 로컬 실행

Node.js 22 이상이 필요해요.

```sh
npm ci
npm run dev
```

개발 서버 주소는 실행 후 터미널에 표시돼요. 저장소에 컴파일된 변환 엔진이 들어 있으므로 일반적인 실행과 프런트엔드 수정에는 Rust 설치가 필요하지 않아요. `npm ci`는 MediaPipe 실행 파일을 `public/vision/`에 준비해요.

```sh
npm run build
npm run start:local
```

`build`는 엔진·예시 배치 검증, TypeScript 검사와 Vite 빌드를 수행해요. `start:local`은 빌드된 사이트를 `http://127.0.0.1:3002/`에서 열 수 있게 하고 명령이 끝난 뒤에도 서버를 유지해요. 현재 터미널에서 미리보기를 실행하고 종료하려면 `npm run preview`를 사용하세요.

`npm start`는 `dist/`를 제공하는 정적 서버를 실행해요. 기본 주소는 `http://127.0.0.1:3002/`이고, 환경 변수 `PORT`를 지정하면 `0.0.0.0`에서 해당 포트를 사용해요.

### 엔진이나 기본 예시를 수정할 때

Rust 엔진을 수정할 때는 Rust/Cargo와 `wasm32-unknown-unknown` 타깃이 필요해요.

```sh
rustup target add wasm32-unknown-unknown
npm run build:core
npm run build:welcome
npm run build
```

`build:core`는 Rust 엔진과 소스 해시 목록을, `build:welcome`은 첫 화면의 기본 배치와 해시 목록을 갱신해요. 기본 예시나 `src/original-core.ts`의 설정만 바꿨다면 `build:welcome`부터 실행하면 돼요. 해시 검증에서 멈추면 메시지에 나온 생성 명령을 실행하고 다시 빌드하세요.

### 실행 중 문제가 생기면

| 증상 | 확인할 내용 |
| --- | --- |
| 변환이나 GIF 저장이 오래 걸려요 | 재료 편집창에서 해상도를 낮추거나 조각 크기를 올려 다시 변환하세요. 가로·세로를 두 배로 키우면 조각 수는 약 네 배가 돼요. |
| 얼굴 부분만 선택할 수 없어요 | 재료 사진에서 얼굴이 감지됐는지 확인하세요. 감지하지 못하면 사진 전체로 변환할 수 있어요. |
| 카메라가 열리지 않아요 | HTTPS 또는 로컬 주소에서 열고, 브라우저의 카메라 권한과 기기의 카메라 사용 여부를 확인하세요. |
| 사진 기록이 남지 않아요 | 브라우저 저장 공간이나 저장 제한을 확인하세요. 기록을 저장하지 못해도 현재 사진으로 변환할 수 있어요. |
| 이미지 파일을 읽지 못해요 | 업로드는 25MiB 이하이며 브라우저가 해독할 수 있는 이미지여야 해요. JPG·PNG·WebP로 다시 저장해 보세요. |

브라우저에서 WebAssembly, Worker, Canvas와 이미지 해독 기능이 필요해요. GPU 애니메이션에는 WebGL2를, GIF 생성에는 Worker 안의 OffscreenCanvas를 사용해요.
